## Notes

- **VARCHAR (Access 'Short Text')**: ODBC `column_size` is the declared length in characters (max 255). Access stores Unicode internally; the driver returns `str`. Map to `NVARCHAR(n)` on SQL Server (n = column_size) so non-ASCII (observed: U+00B5, U+00B7, U+2013) round-trips; PostgreSQL `VARCHAR(n)` counts characters, with UTF-8 databases it is fine. SQLite does not enforce length; keep `VARCHAR(n)` as the declared type name if you want to preserve metadata (SQLite accepts it, affinity TEXT). No observed value exceeds its declared size.
- **LONGCHAR (MEMO / Long Text)**: ODBC size 1,073,741,823 (1 GB). Observed max length only 487 chars, but declared capacity must be mapped to an unbounded type: `NVARCHAR(MAX)`, `TEXT`. Never emit `NVARCHAR(1073741823)` (invalid; max is 4000 or MAX).
- **COUNTER (AutoNumber, Long Integer)**: reported size 10, NOT NULL. Maps to a 32-bit integer. When copying, **preserve the source values** (do not regenerate): on SQL Server insert with `SET IDENTITY_INSERT ON` or use plain `INT` + PK; on PostgreSQL use `GENERATED BY DEFAULT` (not `ALWAYS`) and then `setval` the sequence to MAX+1; on SQLite `INTEGER PRIMARY KEY` accepts explicit values. Values do not start at 1 (e.g. `CB` starts at 144265 in the first rows), so gaps are expected.
- **Not present in these databases** (mapping given for completeness, assumption since unobserved): YESNO/BIT -> SQLite `INTEGER` (0/1), MSSQL `BIT`, PG `BOOLEAN` (Access True is -1, convert to 1); DATETIME -> SQLite `TEXT` ISO-8601, MSSQL `DATETIME2(0)`, PG `TIMESTAMP`; CURRENCY (fixed 4 decimals) -> SQLite `NUMERIC`/TEXT decimal, MSSQL `DECIMAL(19,4)`/`MONEY`, PG `NUMERIC(19,4)`; DOUBLE -> `REAL` / `FLOAT` / `DOUBLE PRECISION`; INTEGER (16-bit) -> `INTEGER` / `SMALLINT` / `SMALLINT`; LONG -> `INTEGER`/`INT`/`INTEGER`; GUID (REPLICATIONID) -> `TEXT` / `UNIQUEIDENTIFIER` / `UUID`; OLE OBJECT/LONGBINARY -> `BLOB` / `VARBINARY(MAX)` / `BYTEA`; DECIMAL -> `NUMERIC(p,s)` using column_size/decimal_digits.
- **Nullability**: all VARCHAR and LONGCHAR columns are nullable; COUNTER columns are NOT NULL. Defaults: none reported (column_def empty).
- **Text comparison/collation**: Access compares text case-insensitively. SQLite default is case-sensitive (BINARY), PostgreSQL is case-sensitive, MSSQL default collation is case-insensitive. Natural-key uniqueness that holds only case-sensitively (see schema_inventory.md 2.7) can break on MSSQL. Consider `COLLATE NOCASE` on SQLite key columns if Access semantics are wanted.
- **Text 'numbers'**: all numeric-looking values are stored as text; keep as text (see schema_inventory.md quirks).
